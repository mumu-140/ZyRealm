> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Execution status:** implementation is complete on PR #24 and the historical checklist below is retained as the original execution plan. The authoritative completion evidence is recorded in **Execution Record (2026-09-15)** at the end of this document.

**Goal:** Add process-local live relay visibility and authenticated manual interruption that is terminal, health-neutral, request/round-scoped, and safe for downstream WebSocket reuse.

**Architecture:** Each logical HTTP relay request or WebSocket `response.create` round owns one shared `relayControl` containing a cause-bearing child context plus safe live metadata. A process-local registry exposes snapshots and interrupt-by-ID; attempt clones share the control pointer. Existing durable `RelayLog`, routing health state, replay budgets, and completed-log SSE remain separate.

**Tech Stack:** Go standard `context`, `sync`, `sync/atomic`, existing Gin router/auth/response helpers, existing relay routing model, React 19 + TanStack Query 5 + Next.js 16, existing Node test runner under `web/tests/*.test.mjs`.

**Spec:** `docs/plans/2026-09-15-p0.3-live-request-manual-interrupt-design.md`

## Global Constraints

- No database migration.
- No deployment, compose, image, or production-state changes.
- No local workstation build/test execution; verification comes from GitHub CI or the approved server container path.
- Manual interrupt is terminal for the logical request: no same-credential retry, credential rotation, protocol fallback, or provider failover.
- Manual interrupt must not create provider/credential cooldown, model-suspect state, circuit failure, or outlier evidence.
- WebSocket manual interrupt cancels one `response.create` round only, never the connection-level context.
- Active-state API never exposes raw request/response bodies, Authorization headers, API-key secrets, or channel credential values.
- Live request API/types/query keys remain separate from `RelayLog`.
- P0.3 is single-process only; no distributed cancellation bus.
